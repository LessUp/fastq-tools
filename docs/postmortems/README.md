# 问题复盘库（Postmortems）

记录开发、测试、使用过程中发现的问题：现象、定位过程、根因、修复方案与教训。

## 为什么单独建库

- `CHANGELOG.md` 记录"做了什么"，commit 记录"改了什么"，但都不承载"为什么发生、如何定位"。
- 复盘条目沉淀长期知识，避免同类问题重复踩坑，也便于回溯历史决策依据。

## 目录约定

- 文件命名：`YYYY-MM-DD-<kebab-case-slug>.md`
  - 例：`2026-07-13-gzip-decompress-bottleneck.md`
  - 一条记录一个文件；跨日期的长期问题以首次发现日期为准，后续进展在原文件内追加章节。
- 模板见 [`_template.md`](./_template.md)，新建条目时复制并填充。
- `_` 前缀文件（如模板）不参与索引排序。

## 写作规范

- **事后视角**：写定论，不写流水账。定位过程中的失败假设可保留，但需标注"假设→证伪"。
- **不复述代码变更**：diff 看 commit，复盘只写 commit 链接。
- **中文撰写**，与项目注释规范一致。
- **必填元信息头**：日期、严重度、影响范围、状态、相关 commit、相关 issue。
- **状态字段**：`open` / `fixed` / `monitoring` / `wontfix`。状态变更时更新该字段并在文末追加日期注记。

## 严重度定义

| 级别 | 含义 |
|------|------|
| S0 | 阻断核心功能或 CI，无可用 workaround |
| S1 | 核心功能受损，有 workaround |
| S2 | 非核心功能问题或体验退化 |
| S3 | 文档/构建/工具链小问题 |
