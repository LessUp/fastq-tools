# 研究附录

研究附录是主白皮书结论已经清楚之后才应该打开的那一层。它不是学习第一个命令的地方，而是用来回答“这些主张有什么来源支撑？”、“它和周边工具怎么比较？”以及“为什么今天的边界会被这样定义？”

## 这一层包含什么

- [`书目`](./bibliography) 收集支撑当前叙事的论文、规范、RFC、库文档与项目主页；
- [`相关项目`](./related-projects) 把 FastQTools 与 FastQC、fastp、Cutadapt、seqtk 放回同一语境下比较范围、接口边界与证据风格；
- [`演进说明`](./evolution-notes) 解释架构决策、benchmark 政策与文档分层如何逐步汇聚成今天的系统叙事。

## 参考文献

当你需要格式背景、benchmark 术语来源或对照材料出处时，请先进入 [`书目`](./bibliography)。

## 什么时候该看研究层

遇到下面这些情况时，研究层最有价值：

- 你需要引用外部来源或内部 RFC，而不是靠记忆转述；
- 你需要解释 FastQTools 与周边 QC / 预处理工具的差别，但又不想把比较写成功能竞赛；
- 你需要理解 benchmark 政策、内存策略与文档边界为什么会被显式写成维护中的规则。

## 与其他文档层的关系

如果你还需要主产品叙事，请回到 [`白皮书`](../whitepaper/) 与 [`架构`](../architecture/)；如果你已经知道问题是什么、只想查精确命令或接口，请转到 [`参考导航`](../reference/)；研究层被刻意放在两者之间，负责提供技术语境，而不直接替代操作手册。

## 设计演进

当问题不再是“怎么运行”，而是“为什么这个边界会被这样选择并持续维护”时，请进入 [`演进说明`](./evolution-notes)。
