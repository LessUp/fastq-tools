# 研究附录

研究附录不是产品手册，也不是贡献流程说明。它更像白皮书后面的附录部分：把对照阅读、文献来源、历史上下文与未来思考收拢在一起，帮助读者把 FastQTools 放回更大的 FASTQ/QC 语境中理解。

## 相关项目探究

比较 FastQTools 与同类 FASTQ/QC 工具的定位、接口边界与性能表述方式。

这类比较的重点不是“列一个冠军榜”，而是看不同工具如何选择自己的边界：有的强调一体化预处理，有的强调单一命令的便携性，而 FastQTools 更强调工程化流水线、可解释的性能证据与清晰的接口层次。

## 参考文献

列出论文、规范、官方文档与关键仓库。

建议优先关注三类来源：FASTQ 格式与质量值背景、行业常见 QC / trimming 工具的官方文档，以及 FastQTools 自身依赖或对标对象（例如 oneTBB、FastQC、fastp、Cutadapt、seqtk）。这些材料共同决定了白皮书里术语、边界与对照方式的可信度。

## 演进思考

解释当前设计为何成立，以及未来可能的扩展方向。

当前设计之所以成立，是因为项目刻意把“叙事层”“参考层”“维护层”拆开：先建立定位，再提供操作，再沉淀维护知识。未来如果扩展更多命令、更多语言绑定或更细的 benchmark 体系，也应该继续沿着这种分层思路演进，而不是把所有信息重新堆回一个入口页。
