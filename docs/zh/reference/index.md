# 参考导航

这一页不是“所有页面的平铺目录”，而是一个**按读者意图分流的入口**。当你已经决定继续使用 FastQTools，下一步通常不是继续读叙事，而是尽快找到最合适的深度手册。

## 如果你现在要……

### 1. 立刻运行一个命令

先读：

- [`快速开始`](../guide/getting-started) —— 用最小步骤跑通安装、构建与第一次执行；
- [`CLI 参考`](../guide/cli-reference) —— 查所有命令、选项与示例；
- [`配置说明`](../guide/configuration) —— 当你需要环境变量、配置文件或默认值说明时。

**适合你如果：** 你是第一次接触项目，或者你只想确认当前任务能否用 CLI 完成。

### 2. 把命令纳入生产或自动化流程

先读：

- [`CLI 参考`](../guide/cli-reference)
- [`部署指南`](../guide/deployment)
- [`工作流`](../workflows/)
- [`性能总览`](../performance/)（如果吞吐与资源是门槛）

**适合你如果：** 你已经理解命令功能，正在考虑容器化、CI 集成、批量运行或环境一致性。

### 3. 把 FastQTools 嵌入 C++ 应用

先读：

- [`API 概览`](../api/overview) —— 先看公共入口与模块关系；
- [`IO 模块`](../api/io) —— 理解记录视图、批处理与 I/O 接口；
- [`处理模块`](../api/processing) —— 理解 predicates、mutators 与流水线；
- [`统计模块`](../api/statistics) / [`核心模块`](../api/core) —— 按实际需求下钻。

**适合你如果：** 你已经不满足于 shell 调用，需要复用内部能力或做更深集成。

### 4. 理解内部实现与维护约束

先读：

- [`架构`](../architecture/)
- [`开发者架构设计`](../dev/architecture)
- [`核心设计`](../dev/design)
- [`构建指南`](../dev/build)
- [`测试策略`](../dev/testing)

**适合你如果：** 你要提交补丁、排查问题、验证设计边界，或准备长期维护项目。

### 5. 审查发布状态、变更历史与协作方式

先读：

- [`变更记录（双语，英文优先）`](../release-notes/changelog)
- [`参与贡献`](../contributing)
- [`资源中心`](../resources/)
- [`归档概览`](../archive/)

**适合你如果：** 你关心版本脉络、开放协作入口、历史迁移背景。

## 什么时候应该离开“参考层”回到“叙事层”

如果你在阅读细节时突然发现自己不确定：

- 这个模块为什么存在；
- 性能数字意味着什么；
- 项目真正的定位与边界是什么；

那说明你应该暂时离开具体手册，回到：

- [`为什么选择 FastQTools`](../why-fastqtools/)
- [`架构`](../architecture/)
- [`性能总览`](../performance/)

参考文档负责回答“怎么做”；叙事文档负责回答“为什么这样做”。两层配合读，效率最高。
